# BubbiFeed

BubbiFeed is Nfusia's simple, gentle baby-feeding tracker, designed for quick,
one-handed use during night feeds. Log breastfeeding, bottles and solids, switch
between baby profiles, and review feeding history and daily summaries.

The product was previously called FeedMyBaby. This is a **display-brand rename**,
not a new application or a data migration. Existing profiles, feeding records and
settings remain in the same app storage; do not uninstall or reset the app to rename it.

## Project

- Mobile app and web preview: Expo SDK 56, React Native and Expo Router, in
  [`src/app`](src/app).
- Shared UI and existing design tokens: [`src/components`](src/components) and
  [`src/constants/theme.ts`](src/constants/theme.ts).
- Companion website: static HTML/CSS in [`site`](site), with its own
  [local preview and deployment reference](site/README.md).
- Editable bottle-and-heart artwork: [`assets/brand`](assets/brand).
  See the [brand rules](assets/brand/README.md); the artwork and palette are unchanged.

## Local development

Read the [project instructions](AGENTS.md) and the exact
[Expo SDK 56 documentation](https://docs.expo.dev/versions/v56.0.0/) first.
Use the existing dependencies when available; the rebrand does not require an upgrade.

From the repository root:

```sh
npm start
# Web preview (same app, not the companion website):
npm run web
```

For a fresh checkout only, follow the dependency/lockfile guidance in
[`AGENTS.md`](AGENTS.md). The historical EAS lockfile workaround is intentionally
unchanged. Do not run the template reset script on this existing product.

## Local checks

```sh
npx tsc --noEmit
npm run lint
npx expo config --type public
```

The existing [UI screenshot helper](scripts/ui-check.js) uses a running local Expo
web server, a locally available Puppeteer Core installation and macOS Chrome. Its
data is synthetic and written only into a fresh browser session. Screenshots are
gitignored. Native behavior still requires testing a built app on a device.

See the [rebrand audit](plans/bubbifeed-rebrand.md) for the actual checks performed,
limitations and intentionally retained identifiers. There is no unit-test script
configured in the project manifest.

## Brand and compatibility

The user-facing spelling is **BubbiFeed**; the ordinary lowercase brand spelling
is **bubbifeed**. Application identity, storage keys, service linkage and existing
URLs are separate from the display brand and must not be renamed automatically.

- The display name is configured in [`app.json`](app.json:3). Native directories
  are generated, not tracked; the next authorized build generated from this config
  will use the new name. Existing ignored native snapshots on this machine still
  have old generated labels; they were not overwritten or regenerated by the rename.
- Existing application and EAS identifiers remain unchanged. The private package
  name is also retained as an internal tooling identifier, not a display brand.
- Website: [BubbiFeed at Nfusia](https://nfusia.com/feedmybaby/).
- [Privacy policy](https://nfusia.com/feedmybaby/privacy.html) ·
  [Support](https://nfusia.com/feedmybaby/support.html) ·
  [support@nfusia.com](mailto:support@nfusia.com).

These are the existing addresses, not a domain migration. Nfusia remains the
publisher. Store listing edits, native builds, deployments and any future domain
or mailbox changes require separate authorization; none is performed by this rename.
